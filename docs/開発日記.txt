モバイルアプリで「RangeError: Invalid time value」エラーが発生していたため、日付処理のバリデーションを追加した

- widgets/フォルダ: MobileCalendar→CalendarMiniWidget, MobileDaySchedule→DayScheduleMiniWidget, MobileTodoList→TodoListMiniWidget  
- ui/フォルダ: Header→SimpleHeader

これでファイル名の混乱が解消され、デバッグやメンテナンスがしやすくなった

その他の改善点:
- デイスケジュールをFlatListからSectionListに移行し、日付ヘッダーをスティッキー表示（上部固定）にした

同期機能の堅牢化:

1/17
オフラインキューとクラウド削除時のコンソールエラーを修正した。

**発生していた問題:**
- オフラインキュー処理時とTodo削除時に `[OfflineQueue] Failed to process item: "xxx" {}` や `Cloud delete error {}` のようなエラーがコンソールに表示されていた。
- エラーオブジェクトが `{}` と表示され、デバッグが困難だった。

**原因と修正:**
1. **エラーシリアライズの問題**: Supabaseの `PostgrestError` オブジェクトは通常のオブジェクトとして `console.error` に渡すと空オブジェクトとして表示される → エラーの `message`, `code`, `details`, `hint` を明示的に展開してログ出力するよう修正。
2. **認証タイミングの問題**: オフラインキュー処理時にセッションが切れている可能性があった → `processOfflineQueue` 関数の冒頭でセッションチェックを追加し、セッションがない場合はキュー処理をスキップ。
3. **dataService.ts**: `JSON.stringify` を使用してエラーオブジェクト全体を詳細に表示するよう変更。

**検証結果:**
- ブラウザで動作確認を実施し、タスク削除が正常に動作することを確認。
- 以前発生していたエラーが発生しなくなったことを確認。

1/20
**スケジュール・カレンダー連携バグの修正:**
モバイル版で、デイスケジュールをスクロールして月を跨いだ際、カレンダーの表示月が連動しないバグを修正した。
- **原因**: `HomeCalendar` が親コンポーネントからの `currentDate` の変更を監視していなかった（初期表示のみ設定されていた）。
- **対応**: `useEffect` を追加し、`currentDate` が現在の表示月以外になった場合、自動的に表示月を移動するように修正。
- **範囲拡張**: ついでに、デイスケジュールの表示範囲を前後30日から前後365日に拡張し、遠い日付へのジャンプでも正しく表示されるようにした。

**デイスケジュールの追記修正:**
- **スクロール同期**: `viewabilityConfig` の閾値を `50%` から `10%` に変更。スケジュールスロットが縦に非常に長いため（〜1300px）、画面の半分を占有する条件が厳しすぎ、スクロールしてもイベントが発火しない問題を修正。
- **描画崩れ**: `getItemLayout` を削除。計算誤差によるコンテンツ消失（白紙化）を防ぎ、標準の計測処理に任せることで安定化させた。

これでユーザーからの意見を収集する準備がモバイルでも整った（あとはサーバー同期連携を待つのみ）。

これで「フェーズ 5: モバイル版の仕上げ」の一つであるシェア機能が完了した。
広告実装を残すのみとなった。

**デイスケジュールの全面リライト:**
SectionListベースの実装でパフォーマンス問題と描画バグが多発したため、FlatListベースで完全に作り直した。
- **アーキテクチャ変更**: SectionList → FlatList に変更。インデックス計算がシンプルになり、`getItemLayout`が安定して動作するようになった。
- **初期位置**: `initialScrollIndex={RANGE}` で今日の日付を即座に表示。`scrollToLocation` や `contentOffset` のワークアラウンドが不要に。
- **範囲縮小**: ±90日 → ±30日 (61アイテム) に縮小し、メモリ使用量とレンダリング負荷を削減。
- **メモ化**: `DayItem`, `TimeSlot`, `CurrentTimeIndicator` を全て `React.memo` でラップ。
- **安定化**: `viewabilityConfig` と `onViewableItemsChanged` を `useRef` パターンで固定し、警告を解消。

長い間悩まされてきたスケジュールの挙動のバグが解消された

**パフォーマンスチューニング (VirtualBox Optimization):**
初期セットアップ後、Linux Mintの動作が非常に重い（マウスの遅延、描画カクつき）問題が発生。以下の対策を実施し、劇的なパフォーマンス改善を確認した。

1. **Hyper-V干渉の排除 (Windows設定)**:
   - 症状: タスクバーのVirtualBoxアイコンが「亀（遅いモード）」表示になっていた。
   - 原因: Windowsの「Hyper-V」「仮想マシンプラットフォーム」が有効で、VirtualBoxのネイティブ仮想化を阻害していた。
   - 対策: `Windowsの機能の有効化または無効化` から関連機能を全てオフにし、コア分離（メモリ整合性）も無効化。
   - 結果: アイコンが「青いV（速いモード）」に変わり、CPU本来の性能が出るようになった。

2. **VM設定の最適化**:
   - **グラフィックス**: `VMSVGA` コントローラー + 3Dアクセラレーション有効化。ビデオメモリを128MBに増強。
   - **CPU**: 割り当てを6コアから **4コア** に削減。
     - *理由*: ホスト(Windows)とゲスト(Linux)でのリソース競合（スケジュール待ち）を防ぐため、物理コア数に対して余裕を持たせるのがベストプラクティス。
   - **入力デバイス**: ポインティングデバイスを `USB Multi-Touch Tablet` に変更。
     - *効果*: マウスの座標ズレとスクロールの引っかかりが解消。
   - **BIOS/System**: `PAE/NX` を有効化。`Nested VT-x/AMD-V` を有効化（将来のAndroidエミュレータ用）。
   - **ストレージ**: 「ホストのI/Oキャッシュを使う」を有効化。

3. **Guest Additions の完全適用**:
   - `sudo ./VBoxLinuxAdditions.run` を端末から実行して再インストール。
   - これにより、高解像度表示（フルスクリーン）とシームレスなマウス統合が機能するようになった。

## 2026-03-08 ルーティンTodoの同期不具合修正 (Mobile)

「曜日指定でTodoを作成した際、他端末に1つしか同期されない」という不具合を修正。

**原因:**
Mobile側でルーティンTodo(複数日分)を作成した際、ローカルのSQLiteには全件保存されていたが、同期をトリガーする `notifyChange` イベントには実装ミスで「最初の1件 (`todos[0]`)」しか渡されておらず、通信を担当するHooksが1件分しかSupabaseにアップロードしていなかった。

**対応:**
1. `shared/storage/interface.ts` の `onDataChange` で配列データを受け取れるように型を拡張
2. `SQLiteRepository.addSRSTodos` の変更通知で配列全体を渡すように修正
3. `useMobileRealtimeSync` 側で、配列で受け取ったデータを1回のネットワークリクエストでSupabaseへ一括Upsertするように修正（オフライン時のキュー登録も配列全件に対して行うように対応）
4. （追加確認で発見した不具合対応）`useMobileSync.ts` にて、ログイン時にクラウドにデータが存在する場合にSQLiteのデフォルトデータをPushしようとしてSupabaseのRLS違反(USING expression)が発生する問題に対応。Web版と同様に事前にローカル初期データを削除するように修正。あわせて `useMobileRealtimeSync.ts` 内の `srs_profiles` テーブル名の監視typoを修正。
