# Mobile App Requirements (Mobile Layout V2)

本ドキュメントは、PomArc モバイルアプリ（Expo）の公式要件定義書です。
**方針**: PC版と同等の全機能をモバイル環境で提供する。閲覧用ではなく、メインの操作端末としても利用可能なフル機能アプリを目指す。

## 1. プロジェクト概要
*   **プラットフォーム**: iOS / Android (Expo)
*   **主要な目的**: PC版 PomArc の機能を完全移植し、モバイル向けの最適化されたレイアウトで提供する。
*   **データ構造**: PC版と同様（SQLiteを使用し、ローカルファーストで動作）。

## 2. 画面レイアウト要件
画面は上から下へ、以下の順序で構成する。

### 2.1 最上部 (Header Area)
1.  **広告バナーエリア**: 最上段に配置。
2.  **ヘッダー**:
    *   **左端**: プロフィールアイコン（ユーザー設定やステータス）。
    *   **中央**: 現在の日付表示。
    *   **右端**: 設定ボタン（アプリ設定、表示設定など）。

### 2.2 メインエリア (Central Split View)
画面中央部は2カラム構成とする。
*   **左カラム**: **Todoリスト**
    *   その日のタスク一覧。
    *   完了/未完了の切り替え、詳細表示。
*   **右カラム**: **Dayスケジュール**
    *   時間軸（バーチカル）でのスケジュール表示。
    *   ドラッグ&ドロップや長押しによる直感的な操作（PC版同等）。

*(注: スマホ縦画面での2カラム表示は幅が狭くなるため、横スクロールまたは比率調整の実装詳細を詰める必要あり)*



### 2.3 カレンダーエリア (Lower Center)
*   **カレンダー**:
    *   メインエリアの下段に配置。メインエリアとの境界をドラッグまたはタップで調整可能とする（要検討）。
    *   **デフォルト表示**: 「3週間表示」（当日が含まれる週、前週、翌週）とする。
    *   **拡大機能 (Expansion)**:
        *   **スワイプ操作**で拡大。
        *   カレンダー領域を上方向にスワイプすると拡大し、1ヶ月表示に切り替わる。

### 2.4 インタラクション要件 (Zoom/Expand Logic)
1.  **スクロール**: Todoリスト、Dayスケジュール、カレンダーはそれぞれ独立して縦スクロール可能。
2.  **拡大挙動 (Maximization)**:
    *   **トリガー**: **スワイプ操作** (Swipe)
        *   **Todoリスト**: **右方向**へスワイプして拡大。
        *   **Dayスケジュール**: **左方向**へスワイプして拡大。
        *   **カレンダー**: **上方向**へスワイプして拡大。
    *   **Todoリスト拡大時**:
        *   Dayスケジュールの「右端 10%」を残して横幅を拡大。
        *   カレンダーの「下端 10%」を残して縦幅を拡大。
    *   **Dayスケジュール拡大時**:
        *   Todoリストの「左端 10%」を残して横幅を拡大。
        *   カレンダーの「下端 10%」を残して縦幅を拡大。
    *   **カレンダー拡大時**:
        *   全月（1ヶ月分）が表示されることを最優先とする。比率はこれに準じる。

3.  **縮小（復帰）挙動**:
    *   **トリガー**:
        *   各領域を逆方向にスワイプ（例: カレンダーを下にスワイプ）。
        *   または、縮小された他領域の残存部分（10%エリア）をタップ。
    *   デフォルトの分割レイアウトに戻る。

### 2.5 アクションエリア (Bottom Footer)
最下部に主要なアクションボタンを固定配置する。
1.  **テンプレート作成**: カテゴリやSRSプロファイルの作成・編集。
2.  **Todo作成**: 新規タスク追加モーダルの起動。
3.  **レポート**: アクティビティ/分析画面への遷移。

## 3. 機能要件
PC版の機能をすべて網羅する。
*   **タスク管理**: 作成、編集、削除、並び替え、期限設定、優先度。
*   **タイマー**: ポモドーロ、カウントダウン、ストップウォッチ。
*   **テンプレート**: カテゴリ管理（階層構造）、SRS設定。
*   **分析**: 学習履歴、統計グラフ。
*   **デザイン整合性**: アイコン、ボタン名称、配色などは可能な限り **Web版 (`apps/web`) と一致** させる。
    *   Web版で使用している `lucide-react` アイコンに対応する `lucide-react-native` を使用する。
*   **その他**: ダークモード対応。

## 4. データ・アーキテクチャ
*   **DB**: `expo-sqlite`
*   **Repository**: `SQLiteRepository` (実装済み)
*   **共通ロジック**: `packages/shared` 内の型やユーティリティをPC版と共有。
